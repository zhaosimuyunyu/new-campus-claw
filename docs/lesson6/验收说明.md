## 启动与入口

先构建执行环境镜像（首次需下载 Chromium 与依赖）：

```powershell
docker compose --profile build build sandbox-image
docker compose up --build -d
```

访问 http://localhost:5173 ，登录并进入课程 → 能力中心。启动时 `bootstrap_tools` 会握手并发现官方 SDK 实现的本地 MCP 服务；学生也可以绑定平台工具，不必拥有服务管理权限。已有数据库、资料与账号保留。脚本执行容器每次新建并在结束时清理。

## 必须回答的五个问题

### 1. 每次对话的具体参数和返回是什么？模板会传入吗？

会。打开当前对话后进入「运行追踪」，按时间选择运行，展开每轮 `llm_request` 与 `llm_response`，或导出 JSON。OpenAI 兼容接口的实际请求体包含 `model`、`stream: true`、`messages`，存在候选工具时还包含 `tools`。`messages` 的 system 包含平台约束、应用角色、变量展开后的提示词模板、绑定技能摘要和命中知识片段；后续跟历史与当前用户输入。附件按模型格式加入当前消息。Anthropic 接口对应 `system`、`messages`、`max_tokens` 与转换后的工具声明。

`llm_response` 保存原始 SSE JSON 帧（包括供应商返回的 id、model、choices/delta、finish_reason、usage 等实际字段），并聚合正文与工具调用。下一轮模型请求会追加 assistant 的 `tool_calls` 与 tool 的执行结果。请求头与认证密钥不写入追踪；mock 明确标记 `sent: false`，不能用它冒充真实调用。

### 2. 绑定知识库后会把全部内容交给模型吗？

不会。先在当前课程范围内进行关键词与向量混合检索、融合排序，仅把最多 4 个命中片段的标题、位置与正文加入 system。`retrieval` 记录本次 query、top_k 和 returned_chunks，可与请求消息逐项对照。没有命中时返回「资料中未找到相关内容」，本次不请求 LLM。索引时的 embedding 请求用于建立或查询向量，和回答时的 LLM 请求是两个步骤。

关闭资料检索，且未显式绑定「课程资料研读」技能时，模型的候选工具也移除知识检索工具，避免关掉 RAG 后又被工具间接触发。显式绑定该检索技能意味着仍允许模型按需发起检索。

### 3. 绑定 Skill 后会传入全部技能内容吗？

初始请求仅包含所绑定技能的 id、名称、简要描述，以及 `read_skill`、`read_skill_resource`、`run_skill_script` 的工具声明。没有绑定的技能不会进入本轮请求。执行前，模型调用 `read_skill`，宿主只返回该技能的完整 SKILL.md 与参考文件名清单；此后通过 tool 消息传入下一轮请求。参考文件和脚本源码仅在 `read_skill_resource` 时按指定路径读取，不把整个资源目录直接放入提示词。

实际执行脚本时，执行器会接收该技能的资源文件，以支持相对路径依赖；这些输入属于隔离执行服务，不等于全部发给 LLM。

### 4. 执行 Skill 的逻辑是什么？

绑定 → 提供摘要与可用工具 → 模型判断适用性 → `read_skill` → 按指令读取参考文件 → 需要时 `run_skill_script` → 执行结果（stdout、stderr、退出码、耗时）作为 tool 消息 → 模型继续回答。

Skill 是任务方法和资源包；MCP 是工具通信协议。带脚本的 Skill 完全可以通过 MCP 执行工具，或通过宿主提供的隔离执行器运行。本项目两条路径均支持：`run_skill_script` 执行上传包中 scripts/ 下的 Python/JavaScript/Shell；MCP `python_execute` 与 `shell_execute` 执行动态代码。生成文件存入 `outputs/` 后导出为受账号和课程权限保护的产物。

隔离执行环境预装 Python、Node、Chromium、Playwright、pandas、matplotlib 等。每次使用临时容器，非 root、根文件系统只读、无宿主目录挂载、无 Docker socket、丢弃 capability、限制 CPU/内存/进程数与运行时间。普通脚本无网络；专门的浏览器工具允许公网网页并拒绝内部地址。执行代理自身持有 Docker socket，因此属于受信任基础设施，仅在内部容器网络开放，不能对公网暴露。

原始上游技能涉及 Git、插件、特定工作区和其他专用环境时，平台不会伪称已提供这些环境；其脚本可在支持的运行时执行，缺少的输入或能力必须明确报告。

### 5. 接入 MCP 后每轮向 LLM 发送哪些参数？

连接时宿主使用 JSON-RPC 2.0，依次 `initialize`（协议 2025-03-26）、`notifications/initialized`、`tools/list`。维护最近发现的名称、描述和 inputSchema。只将当前课程助手绑定的候选工具转换成 LLM `tools[].function`：名称 `mcp_<serverId>_<toolName>`、真实描述与 JSON Schema。服务器 URL、会话标识和 Bearer 令牌都不会放入 LLM 工具声明。

模型返回 tool_calls 后，宿主验证候选集、JSON Schema、账号和连接状态，再发送 MCP `tools/call`。成功与失败都记录 tool_result，并作为 tool 消息发送给模型下一轮。最多 12 次工具调用、6 轮模型请求，最后一轮移除工具并要求据已有证据作答。单次脚本 35 秒，MCP/宿主请求另有超时。断开服务器会使后续执行立即拒绝；一项工具失败不会直接终止整个回答。

## 课堂演示步骤

1. 选择「编程搭档」，配置模板「你是 {{course}} 的助教；先给结论，再列证据」。提问并导出请求。
2. 添加「数据分析」技能；要求「读取技能和脚本，用 run_skill_script 计算 12、18、24、30 的平均数与中位数」。预期均为 21，记录中有加载、脚本调用和真实 stdout。
3. 上传 `sample-skill.zip`，添加技能，要求运行其脚本。也可修改 ZIP 自测。
4. 绑定 platform-tools 的 formula_hint、python_execute、shell_execute、browser_open；可先测试工具，再让模型自主调用。
5. 要求打开 https://example.com ，检查真实标题 `Example Domain`、正文和截图产物。
6. 勾选课程资料，问一个与已索引资料匹配的问题，检查 retrieval 只有相关片段。
7. 教师用两个账号交叉验证：个人服务器列表与调用记录隔离，直接访问他人服务器返回 404，列表无令牌原文，断开后工具不可执行。学生可以使用平台公共工具，但服务管理 API 返回 403。
